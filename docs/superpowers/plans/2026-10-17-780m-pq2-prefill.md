# 780M Bonsai PQ2_0 预填充优化 — 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 Bonsai PQ2_0 在 780M 上的 prefill 从 ~520 t/s 推向 ≥1.90× 官方（≈1000 t/s），decode 不回归、输出质量不退化。

**Tech Stack:** llama.cpp prism fork（C++/GLSL）、MSVC 2022 + CMake 4.4.3 + Ninja + Vulkan SDK 1.4.313.2、PowerShell 脚本。

**Spec:** `docs/superpowers/specs/2026-10-17-780m-pq2-prefill-design.md`（执行前先读）

## Review Focus

1. **状态漂移误判**：性能判定必须由脚本强制"交错+中位数+锚健康检查" → T3/T5 实现并验证。
2. **构建差异污染**：parity 门（|Δ|≤2%）在所有优化前跑通；台账记录每个构建的旗标与工具链 → T2/T5。
3. **数值正确性**：任何 shader/kernel 改动（尤其解包/融合）先过 ppl+prompt 门 → T4 提供工具。
4. **运行时变体错配**：优化后确认运行时实际选择的 pipeline/形状符合预期（perf-logger+必要时插桩）→ T7/T8 及每个 E 任务。
5. **大 batch/长序列退化**：pp2048 与生成冒烟覆盖；tg 相对守护 → T5/T20。

## 通用实验协议（所有 E*/Phase 2 任务适用）

1. 明确假设与预期机理（写进任务产出草稿）
2. 打补丁（最小改动；记录文件:行）
3. 构建 lean（`build-vk.bat <name> lean`）+ 快速基准（`-p 512 -n 32 -r 2`，只判方向）
4. 方向不对 → revert；方向对 → 全量交错 A/B（T3 脚本，官方为参考）+ 正确性（T4 脚本）
5. 过门 → commit（信息含改动、前后数字、验证命令）；不过门 → revert + 记录负结果
6. 更新台账 `reports/ledger.md`
7. 任何时刻可用 `git checkout perf/780m-pq2` 回到上一点

### Task 10: E3 解包向量化
**假设**: `load_a` 的 PQ2_0 解包（mul_mm_funcs.glsl:196 起）指令数可压 15-25%（批量位运算、成对 f16 转换）。
**门**: 受影响形状 +15% 级；正确性门通过。

### Task 11: E4 权重复用重构
**假设**: 解包在 N 方向重复率可通过分块重构摊薄（每份解包服务更多 MMA）。预期最大杠杆（7→10T 级）。
**门**: GEMM 聚合 ≥8.5T；正确性门通过。

### Task 12: E5 流水线/LDS 压榨
**假设**: 双缓冲、bank 冲突、fragment 预取可再挖 10-20%。
**门**: GEMM 聚合尽量逼近 12T；记录饱和点。

### Task 13: E6 备选（条件任务）
仅当 T11/T12 后 GEMM <10T：评估 （a）自研 `mul_mm` PQ2_0 变体/更大结构改动；（b）int8 点积路线（需生成器支持）；（c）接受现状转 Phase 2。
