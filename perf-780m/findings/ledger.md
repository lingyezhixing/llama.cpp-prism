- 2026-10-18 **PQ2_0 layout resolved (for E3)**: `block_pq2_0 = {ggml_half d; uint8_t qs[32]}` = 34B/block, no padding (static_assert); GLSL struct stride = 34B; shader `idx` is a *virtual qs-byte counter* (idx/32 = block index, idx&31 = qs byte within block) -> consistent with raw layout. **Consequence: qs lives at block offset +2, so u32 loads are misaligned; byte loads were necessary. u16 loads (+2 aligned) are safe; u32 needs a host repack to 36B blocks (+~12% A memory) -> demoted.** E3-A hence = u16 loads (2x fewer load instrs, modest); **primary next = E3-B (BN2)**: each WG computes 2 adjacent N-tiles sharing ONE A strip per k-block -> A global-load + dequant work halves (A redundancy 8x->4x); mechanism: extra `buf_b2` LDS (8KB; total ~26KB < 32KB cap), host wg_denoms.y 64->128 for the pq2_0 M-slot variant, B1 direct loads (not register-prefetched), inner MMA loop over doubled cms_per_col with B base switch, guard `!MUL_MAT_ID`.
- **E3 design notes (GEMM A-side source recon, 2026-10-17)**: PQ2_0 coopmat1 M-slot: `LOAD_VEC_A=4` (gen `load_vec_quant=4` for pq2_0), `LOAD_VEC_B=load_vec` (f16). Per WG per BK=64 k-block: 1024 idx-units (1 byte = 4 elements each); per thread A_STEPS=8 -> 8 scattered 8-bit global loads + per-idx dequant (ib=idx/32, iqs=idx&0x1f; ~4 ops/elem) + 2 LDS stores. Mapping: loadr_a=tid%16 = byte-in-strip, loadc_a=tid/16 = M-row (thread's 8 idx are strided by 8 M-rows). **E3-A (vectorize)**: remap so a thread loads u32 words (4 consecutive bytes = same M-row) instead of u8 -> 4x fewer/wider loads; extraction via unpack8(word & 0x03030303)-style; mind the LDS k_pair interleave convention (see q4_0 arm). **E3-B (structural, bigger)**: per-WG N-reuse (process 2+ N-tiles per k-block; A strip loaded once per (m-block,k-block)): A redundancy n/BN=8x -> near 1x would reap most of the A-side 12.3% of pass (up to ~+10% prefill).
