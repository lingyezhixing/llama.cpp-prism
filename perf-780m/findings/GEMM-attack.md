# GEMM 结构攻坚 #1 — 脏相位移除探针 (2026-10-18)

目标：把 GEMM(~585ms/pass) 中 MMA(≈26%) 以外的 ~60% 劈开定界。
基线（本会话，warm，builds\probe\bin）：pp512 = 634.8 t/s（首轮 601.8 冷启动弃用）。

## 探针定义（全部只影响 PQ2_0+COOPMAT+!MUL_MAT_ID 编译变体；结果故意错误，仅测性能）

| 探针 | 改法 | 杀死的东西 | 保留的东西 |
|---|---|---|---|
| P1 noLDS-mma | cache_a/cache_b 置常量 | MMA 相位的 LDS tile 读(16A+32B/块/波)；若上层 DCE 级联则含 A/B LDS 写 | WMMA 发射、A/B 全局装载、屏障、epilogue |
| P2 no-producer | A store 与 B store 写常量 | A 解包 ALU + A/B 全局流量 + A/B LDS 写 | MMA 及其 LDS 读、屏障、epilogue |
| P3 no-barrier | 去掉两块内 barrier() | 相位串行/同步 | 一切数据通路 |

GEMM GFLOPS：base ~5900-6430 → P1 ~6900-7515。仪器化 pp512：569.3 → 596.7（仪器化运行本身偏冷/偏慢，仅同口径比较）。

**初步结论（P1+P2 后）**：每块关键路径两侧各 ~15%：生产侧（解包+全局装载+LDS 写）= +15.8%，消费侧（LDS tile 读+依赖）= +15.1%。两者近乎相等且各自干净（互不包含对方）。绝对量级：pass 787ms × 15% ≈ 118ms 每侧；base GEMM 585ms ≈ MMA 205 + 生产 ~118 + 读 ~118 + 同步/尾巴 ~144。→ 主攻方向 = **让两侧重叠 + 减少两侧自身成本**：
1. 读侧：批量装载 tile（每 i 步先 2×B + 4×A 装载再发 8 个 MMA；同时消灭 B 的 4x 重读）→ 候选 R1a。
2. 生产侧：LDS 写减半（f16vec4 合并写，数学等价）→ 候选 R2；解包 ALU 重访（E3-A 教训：谨慎）。
3. 重叠：双缓冲流水线（BK=32 全双缓分 20.5KB 可行；BK=64 全双缓 38.8KB 超 32KB 上限；A 双 B 单 29.6KB 可行）→ 视 P3 同步占比决定。

## 战役收尾（2026-10-18）

**已采纳**：R1a（提交 `07c6de565`）：8 轮 A/B **pp512 1.0284 / pp2048 1.0270 / tg128 0.9975**；正确性 ppl Δ=0 + 6/6 逐位一致（位精确）。

**三静脉全图与墙**：

| 静脉 | 移除探针上界 | 攻击手段 | 结果 | 墙判定 |
|---|---|---|---|---|
| MMA 相位 LDS 读 | +12~15% | R1a 批量去冗余 | +2.8% 采纳 | coopMatLoad 固有单次开销（对齐/冲突已最优：PAD=4 甜点） |
| 生产侧（A 解包+LDS 写 + B 全局） | +13%（B≈8, A≈5） | R4' B双缓 / R7 B寄存器 / E3-A | −16% / 史证−2% / −1.1% | B = L2→CU 带宽墙（377MB/dispatch≈97GB/s）；A = 结构不可拆 |
| 相位同步/屏障 | +10%（P3） | R9 warp 私有化 | −10.4% | 屏障本身不可回收；P3 收益源于探针的非结构自由漂移 |
| 矩阵单元余量 | — | — | — | P1（全部 LDS 读移除）后 GEMM ≈7500 GFLOPS ≈45% 峰值，每 WMMA 实占 ≈30cy vs 理论 16cy → 余量散布于上述三项，无单点大块 |

**结论**：GEMM 结构级余量被"驱动代码生成峭壁（BM/BN 扩大即崩塌）+ L2 带宽 + VGPR 悬崖"三墙锁定；本会话结构性可得已收割（R1a）。累计对官方 ≈ **1.2371（pp512）/ 1.2206（pp2048）**（1.2029/1.1885 × 本会话收益）。

**含义**：wave32（+4.5~6%）吃掉的正是"延迟暴露"类开销；剩余静脉稀薄（P1+P2b 合计 ~8%，且各自的修复路径在 wave64 时代已逐一实测封闭——R1b/R4'/R7/R9 皆负）。**GEMM 结构线到此实为收干**；剩余选项只有非 GEMM 小项（~+0.5%）。



| R1b | A 每步一个不动点：把 i+1 步的 tile 装载提到 i 步 MMA 之前（寄存器软流水；双套 fragment） | 隐藏 LDS 读延迟 | **1.0193**（tg32 0.986）→ +1.9%，不如 R1a → 读延迟假说证伪；暂存 R1a |
| R2 | store_a_pq2_0 合并为 1×f16vec4 写（16→8 条 LDS 写/线程/块，数学等价） | 吃 P2 的一小块 | 需 alias 技巧，低优先 |

| R6 | 装载相位先发 B 全局装载再 A 存储 | 被 R4' 取代 | 取消 |
| R7 | B 寄存器预取（+16 VGPR） | — | **历史已否决**：E5A→E5A+ 实验（ledger）：B 预取寄存器每程 ≈−2%，去掉后 +3.71% 采纳 → B 延迟隐藏无效 |
| R8 | APPLY_SLM_A_RESHAPE=1（spec13，A 在 LDS 改为 TK/2 宽块布局 → coopMatLoad 连续 512B） | 若 coopMatLoad 地址/冲突开销被 reshape 摊平 → 吃 P1 静脉 | **构建中（host env GGML_VK_PERF_RESHAPE）** |

**B 静脉最终判断（P2b+R4'+E5A 史实）**：B 的 ~8% 不是"延迟"（隐藏两法皆败），是 **L2→CU 带宽**（每 dispatch B 流量 ≈ 377MB = K×N×2B×M/BM；L2 需求 ~97GB/s）。唯一治本是降流量（↑BM 或 N-reuse），但 BM=128 是驱动悬崖、双 M-tile 需 +32 VGPR 累加器（≈−5%）→ 目前判定：**B 静脉暂不可挖**。


**R1a/R1b 结论**：寄存器批量/软流水都只拿 +2-3% → MMA 相位的读代价不是"装载延迟"或"条数冗余"主导；最可能是 LDS bank/端口固定成本（每 coopMatLoad 的固有多周期成本）→ R3 直接检验 bank 冲突假说（PAD=0 若崩塌、PAD=1/2/3 若显著抬升则实锤）。




## 判读规则（预注册）

- **P1 掉 <10%**：LDS 读路径不是瓶颈 → 查屏障/延迟/频率墙，重估"MMA busy 26%"口径。
- **P1 掉 20-40%**：MMA 相位 LDS 读是大头 → 攻 read 冗余与列主序访问（cache_b 每 i 只读一次/预载碎片/加 pad）。
- **P2 掉 >20%**：生产侧(全局流量+解包+写)是大头 → 攻 u32 载入打包、f16vec4 写、解包降 ALU。
- **P3 掉 >15%**：相位串行是真凶 → 上双缓冲流水线（LDS 预算：BK=64 全双缓冲 38.8KB 超 32KB；A 双 B 单 = 29.6KB 可行）。
- 数值互相矛盾时（如 P1+P2 远超总时间）：怀疑 DCE 级联，按"上界"解读并追加细分探针。
